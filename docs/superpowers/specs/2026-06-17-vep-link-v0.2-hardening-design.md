# vep-link v0.2 — Hardening & Allele-Correctness Design

**Date:** 2026-06-17
**Status:** Approved (full v0.2 scope; clean-break schema; phased delivery)

> Historical record — this document records the approved v0.2 hardening design.

**Supersedes/extends:** `2026-06-16-vep-link-design.md`, `2026-06-16-upstream-health-design.md`

## Problem

LLM-consumer testing of the live MCP (19 calls across all 7 tools) surfaced four
correctness defects, a token-efficiency weakness, and a runtime observability gap.
The infra/facade layer rates ~9/10; the functional data path drags the server to
~6.8/10. v0.2 fixes the defects, makes allele ambiguity *visible* instead of
silently wrong, and removes duplicated payload — targeting a defensible >9/10.

### Re-baseline: the tested server was stale

`git diff main..HEAD` is empty — the token-efficiency + observability work is
**already committed on `main`** (commit `f170c9f`). The live MCP instance used for
black-box testing predates it, which produced misleading symptoms (CADD per
transcript, `elapsed_ms:0`, `fields` apparently ignored). Re-baselined against
source, the work splits cleanly:

**Already implemented on `main` — NOT work for this effort; the action is to
redeploy the stale instance and guard parity:**
- CADD/GERP hoisted to a variant-level `position_scores` object and removed from
  per-transcript rows (`extraction.py:35-59,194-212`).
- Per-transcript null-stripping (`shaping.py:_project_transcript`, `:116-124`);
  transcript filtering + cap + `transcripts_summary`; `transcripts="auto"/"all"`
  (`shaping.py:170-205`); `DEFAULT_MAX_TRANSCRIPTS=10`.
- Wall-clock `elapsed_ms` via `_stamp_elapsed` (`errors.py:222`); a Prometheus
  `METRICS` registry + `GET /metrics` endpoint (`observability/metrics.py`,
  `server_manager.py:138`); `recode` already echoes `input`/`id` (`_recoding.py:69`).

**Genuine bugs / gaps in current `main` source (the real work):**
1. **Batch not resilient to one bad input** — `vep_service.py:175-183`. The
   per-input loop only catches `VariantParseError`/`DataNotFoundError`; the recoder
   call at `:96` can raise `EnsemblApiError`/`RateLimitedError`/`UpstreamTimeoutError`,
   which escape and abort the whole batch — violating the method's own docstring
   ("never fail the whole batch").
2. **`recode` default returns vcf_string only** — `vep_service.py:260` uses
   `fields or "vcf_string"`, so *omitting* `fields` fetches vcf_string ONLY,
   contradicting the tool's "omit for the default set" (should return the full
   representation set). The fetch-layer `fields` filter itself works.
3. **Multi-allelic input resolves to one silent alt** — `_recoding.py:35-52`.
   `first_canonical_vcf_string()` returns the first matching VCF string with no
   ambiguity detection; `rs6025` (C>T and C>A) silently yields one alt, order-
   dependent — and the picked C>A / p.Arg534Leu is *not* the canonical Factor V
   Leiden allele (C>T / p.Arg534Gln).
4. **`liftover_variant` does no REF validation** — `vep_service.py:282,305`.
   Assembly-map is coordinate-only; input REF/ALT are carried through unchanged, so
   the lifted REF can be wrong (`1-169549811-C-A` → `1-169519049-C-A` while
   `resolve(rs6025, GRCh37)` gives `1-169519049-T-C`).
5. **Error-code/recovery drift** — `errors.py`. A same-assembly liftover raises
   `UpstreamInputError` (local validation) but the recovery reads "Ensembl rejected
   the request" though Ensembl was never called; unrecognized free-text → code
   `invalid_input` while the message says "No variant found" (reads as `not_found`).

## Locked decisions

- **Scope:** full v0.2 — correctness + token + new capabilities + observability.
- **Compatibility:** clean break, no shim. Bump `__version__` and
  `CAPABILITIES_VERSION` to a 0.2.0 line; document the schema diff in
  `get_capabilities`. No legacy response shape retained.
- **Multi-allelic:** return all ALT alleles (array contract), not a silent pick.
- **Liftover REF:** validate the lifted REF against the target assembly; on match
  return full `CHR-POS-REF-ALT`, on mismatch return coordinate-only + a warning.
- **`variants[]` shape:** always a list (1 element for single-alt inputs) so the
  consumer never branches on shape.
- **Shipping:** Phase 1 (correctness, non-breaking) may ship as `0.1.1`; Phases
  2–4 (schema changes) land together as the `0.2.0` clean break.

## Cross-cutting contracts (clean break)

### Unified `variants[]` result (resolve_variant, annotate_variant)
```jsonc
{ "query": "rs6025", "assembly": "GRCh38",
  "variants": [ { "variant_id": "1-169549811-C-T", ... },
                { "variant_id": "1-169549811-C-A", ... } ],
  "warnings": [ {"code":"multiple_alts",
                 "message":"rs6025 maps to 2 ALT alleles",
                 "context":{"count":2,"alts":["A","T"]}} ],
  "provenance": { ... }, "_meta": { ... } }
```
- Single-alt inputs → `variants` of length 1, `warnings: []`.
- Optional `allele` arg (one ALT base or `CHR-POS-REF-ALT`) filters to that alt.

### Shared `warnings[]` channel (all tools)
Top-level array, empty when none. Entry shape `{code, message, context}`. Codes:
`multiple_alts`, `ref_not_validated`. (Transcript capping is already surfaced by
the existing `transcripts_summary` key in `standard` mode — it stays a key, not a
warning.) Warnings are the honest-signal mechanism; they never replace the error
envelope (which owns hard failures). `warnings` is a top-level key, not under `_meta`.

### Per-variant annotation shape (token-lean)
```jsonc
{ "variant_id":"16-2090952-G-A", "gene_symbol":"PKD1",
  "most_severe_consequence":"stop_gained",
  "cadd_phred":53, "cadd_raw":..., "conservation":1.43,   // hoisted ONCE
  "frequencies":[...],
  "transcript_consequences":[
    { "gene_symbol":"PKD1","transcript_id":"ENST00000262304","impact":"HIGH",
      "consequence_terms":["stop_gained"],"hgvsc":"...","hgvsp":"...",
      "protein_position":"3979","revel":null,"am_pathogenicity":null,
      "am_class":null }       // CADD/conservation removed; null keys stripped
  ] }
```
`revel`/`am_pathogenicity`/`am_class` stay per-transcript — they are
substitution-specific (verified: COL4A5 had REVEL on 2 of N transcripts).

## Design by phase

### Phase 0 — Redeploy & runtime-parity guard (do first; highest impact)
The committed token-efficiency + observability improvements are invisible because
the running instance is stale. Restart/redeploy the MCP server, then add a small
parity smoke test (integration-marked) asserting a live `annotate_variant` carries
a variant-level `position_scores`, no per-transcript `cadd_phred`, and
`_meta.timing.elapsed_ms > 0` — so a stale deploy can never silently mask the code
again. No application-code change; this is ops + one guard test.

### Phase 1 — Correctness (non-breaking; ship as `0.1.1`)
1. **Batch resilience** (`vep_service.py:175-183`): widen the per-input `try` to
   catch every `VepLinkError` subclass (mapped to its code via the shared
   classifier) and any unexpected `Exception` (→ per-input `internal_error`),
   append to `errors[]`, `continue`. `summary.failed` already counts `errors`.
2. **`recode` default = full set** (`vep_service.py:260`): when `fields` is
   `None`, fetch the documented full representation set (pass `fields=None` to the
   recoder so it returns its default, or an explicit
   `"id,hgvsg,hgvsc,hgvsp,spdi,vcf_string"`), not `"vcf_string"`. Keep the explicit
   `fields` filter behavior; have `aggregate_recode_entry()` emit only the fetched
   field keys (no empty-list keys for unfetched fields).
3. **Error-code/recovery accuracy** (`errors.py`): give locally-validated failures
   (`UpstreamInputError` from same-assembly liftover) a recovery that does not claim
   Ensembl rejected the call; map unrecognized-input "No variant found" to
   `not_found` so code and message agree.

### Phase 2 — Token efficiency: **ALREADY IMPLEMENTED on `main`.**
Hoisted `position_scores`, null-stripping, transcript filter/cap, and
`transcripts="auto"/"all"` all exist (`shaping.py`, `extraction.py`). No code
tasks — correctness is verified by the Phase 0 redeploy + parity test. (Optional
rename: the live key is `transcripts_summary`, not the `transcripts_truncated`
named in the cross-cutting draft; keep the existing name to avoid a needless break.)

### Phase 3 — New capabilities (allele correctness; clean break → `0.2.0`)
4. **Multi-allelic expansion**: add `canonical_vcf_strings(payload) -> list[str]`
   to `_recoding.py` returning the **deterministically-sorted distinct** canonical
   alts (keep `first_canonical_vcf_string` or express it as `[0]` of the new list).
   `resolve`/`annotate` fan out to the `variants[]` list (always a list; length 1
   for single-alt); add the optional `allele` arg to filter to one ALT; emit the
   `multiple_alts` warning listing alts + which were returned. Deterministic
   ordering also removes the batch non-determinism.
5. **Liftover REF validation** (`vep_service.py:liftover` + `ensembl_client`): add
   a target-assembly reference-base read (Ensembl `/sequence/region`) for the lifted
   locus. REF matches the carried base → return full `CHR-POS-REF-ALT`; mismatch →
   return coordinate-only (`lifted` without alleles) + a `ref_not_validated` warning
   naming expected vs carried base and recommending `resolve_variant` in the target
   assembly. Gated by `LIFTOVER_VALIDATE_REF` (default true).
6. **`warnings[]` channel**: a shared helper builds the top-level `warnings` list
   (`{code, message, context}`); wired into resolve/annotate/liftover responses
   (empty list when none). Codes: `multiple_alts`, `ref_not_validated`.

### Phase 4 — Observability: **ALREADY IMPLEMENTED on `main`.**
`_stamp_elapsed` populates `elapsed_ms`; `observability/metrics.py` + `GET /metrics`
expose Prometheus counts/latency. No code tasks — verified by Phase 0. (Optional,
out of scope: an MCP-readable `vep://metrics` resource mirroring `/metrics` for
stdio clients that have no HTTP ops port.)

## Config additions (`VEP_LINK_` prefix)
`TRANSCRIPT_FILTER_DEFAULT=relevant`, `LIFTOVER_VALIDATE_REF=true`,
`METRICS_RESOURCE_ENABLED=true`. All overridable; defaults chosen for correctness.

## File-size & structure
All targets are <600 LOC today (`vep_service.py` 307, `shaping.py` 237,
`extraction.py` 243, `_recoding.py` 71, `ensembl_client.py` 160, tool files <90).
`vep_service.py` gains batch-catch + liftover-validation + alt-expansion; if it
crosses ~500 LOC, split `liftover` and/or `batch` into dedicated `services/`
modules (cohesive split per the LOC discipline). No other file is at risk.

## Testing (zero real network; respx-mocked)
New fixtures: multi-allelic recoder payload (rs6025 C>T/C>A), liftover ref-mismatch
(assembly-map + sequence reply), batch partial-failure (valid + upstream-fault +
not-found), fields-filtered recode, delayed-body timing. New/updated unit tests per
fix asserting: per-input `errors[]` + `summary.failed`; `fields` trims payload;
`variants[]` length + `multiple_alts` warning + determinism; hoisted scores absent
from transcripts and present once at variant level; null keys stripped;
`transcripts_truncated`; liftover full vs coord-only + warning; `elapsed_ms > 0`.
`make ci-local` (ruff + lint-loc + mypy + 80% coverage) is the gate. Live behaviors
stay behind `integration` marks.

## Non-goals
No `pick`/per-gene VEP plumbing beyond the relevance filter; no auto-routing between
builds; no server-initiated push (unsupported on stateless HTTP); no OTel exporter
(documented hook only); no re-introduction of per-type VEP GET endpoints.
